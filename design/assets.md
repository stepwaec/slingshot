# Slingshot — asset index (v2)

One row per file in `design/assets/` (9 top-level files, 26 bodies in `bodies/`, 5 environment files in `space/` — 40 SVGs), then the previews and the mockups. All SVGs are self-contained (no scripts, external refs or raster), `xmllint --noout` clean and use only the tokens of `style.md` §2 / §8 / §9. "Anchor" is the point the game positions and rotates. Exact Canvas code is in `canvas-notes.md` (§ numbers below). How to build each asset in the game\'s Three.js renderer is in `threejs-notes.md` (§10 maps every asset to its factory).

**Structure.** Every body and environment asset is `<defs>` (ids prefixed per file) + **one** top-level group `<g id="…" transform="translate(cx cy)">` with all geometry relative to (0, 0), SMIL animation inside, and a **header comment listing every parameter — the header is the canon**. Mockups and galleries copy the defs and the group verbatim and change only the translate (plus scene-local lighting wrappers). Ids are unique across all 37 SVGs (checked: no id defined in two files, every `url(#…)` / `href` resolves). Static renders and mockups show t = 0.

**v1.5 (revised)** retuned every body to the two client-approved references — the ocean world "variant F" (= `planet-start.svg`) and the sun "variant J" (= `star.svg`) — and **v1.4** added the moons, ringed planets and the space environment, built directly to those rules (`style.md` §4.1). Ids removed by the retune, for anyone re-inlining old copies: `starGlow`, `starCorona`, `starStreamerBlur`, `starChromoBlur`, `starPromBlur`, `starGranulation`, `starCoronaBlur` (and the `rd*` / `bg*` equivalents); `bhMottle`, `bhStreakBlur`, `bhStreakFade`, `bhStreakFadeGrad`, `bhPhotonBlur`, `bhArcBlur`; `psSquash`, `psRimLit`, `psRimMask`, `psSurfaceAnim/Strip`, `psCloudAnim/Strip` and the matching `oc* px* rk* ic* lv*` squash / rim-mask / strip ids. New: `starDisc`, `starEdge`, `starSurf`, `starFlame`, `starWisp`, `starRimRag` (and `rd*` / `bg*`), `bhPlasma`, `bhRag`, `bhArcRag`, `bhPhotonRing`, `*Haze`, `*Lit`, `*LitMask`, `psCloudShadow`, `pxWispShadow`, `lvLimb`, `lvCrustAnim`, `lvGlowAnim`, `dbBCapWarp`, … — see each header.

## Usage rules

- **Cached bitmaps.** Every body and environment piece is rendered from its SVG recipe into cached sprites at its CSS size × DPR × the zoom bucket, and only moved per frame (scale, rotation, offset, alpha). DPR is `devicePixelRatio` clamped to [1, 2]; scaled blits use `imageSmoothingQuality = "high"`; a cached sprite is never upscaled beyond 1.25× — it is rebuilt (`canvas-notes.md` §0, §12).
- **Noise.** Canvas builds gradient-noise tiles and maps each field onto Chrome's `feTurbulence` value scale by quantile, so the header slopes and intercepts apply unchanged and zones stay as crisp as the SVG's (`canvas-notes.md` §0).
- **Lighting never rotates.** Overlays (shade with the warm band, lit-side haze and rim, glint) are built for L toward the scene's star; only textures scroll or rotate. Tumbling rocks, wreck pieces and the captured moon use lit frames, never a rotated lit sprite.
- **Glow budget.** Per scene: the star (or compact object) and planet X; the lava halo is the one planetary exception; nebulae are background gas. 0 `shadowBlur` in play; the result card's shadow is the one, drawn once.
- **No blur beyond the references.** No blur above 0.5 on bodies and effects except glows and hazes, the sun's flame / wisp softness (0.4 / 0.8), the lava bloom (0.8), the crack glow (0.9), the toxic field smoothing before its threshold (0.6) and gas (nebula bodies, the dark cloud's tail) — `style.md` §4.1.
- **Crash radii.** The solid disc of every body: planets r, stars 46 / 40 / 54, white dwarf 16, neutron star 8, black hole 22, moons 12 / 13 / 9, systems at the moving centres (double 18 / 11, moon system 26 + 5 / 7, shepherd moons 2.5). Hazes, rims, flames, glows, beams, the capture ring, rings, particles, rocks of the debris ring and the accretion disk are never contact.
- **Previewing the strip SVGs in Chrome.** Most rotating bodies scroll a 2P-wide strip whose noise is computed over one period with `stitchTiles` and repeated with `feTile`. In some clip and transform nestings Chrome skips rendering part of that source tile and `feTile` then repeats empty pixels, so a frame can briefly show a flat block or a hairline at the tile join. It affects only SVG previews in a browser; the game draws its own visuals and the cached-sprite pipeline in `canvas-notes.md` / `threejs-notes.md` never uses `feTile`. Planet X, ice, lava and the icy moon already use the seamless v1.5.1 construction (no `feTile`). To preview another body reliably, view it on its own at 1× or 2× rather than nested in a scaled, clipped container.
- **HUD, path, trail, arrow, ship, thrust, overlays:** unchanged since v1 — see `canvas-notes.md` §5–§11 and `style.md` §6.
