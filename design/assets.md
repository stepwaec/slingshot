# Slingshot — asset index (v1.2)

One row per file in `design/assets/`. All SVGs are hand-authored, self-contained (no scripts, external refs or raster) and use only the palette tokens from `style.md` §2 / the brief. "Anchor" is the point the game positions and rotates. The last column is the gist; exact Canvas code lives in `canvas-notes.md` (§ numbers below).

v1.1 (realism pass) rewrote four files — `star.svg`, `planet-start.svg`, `planet-x.svg`, `starfield.svg`. The three body assets are `<defs>` (ids prefixed `star*` / `ps*` / `px*`, unique across the three files) plus **one top-level group** with all geometry relative to (0, 0): `<g id="star" transform="translate(200 200)">`, `<g id="planetStart" transform="translate(60 60)">`, `<g id="planetX" transform="translate(120 120)">`. Gradients and masks that need positions use `gradientUnits` / `maskUnits="userSpaceOnUse"`, so a mockup copies the `<defs>` and the group verbatim and only changes the `translate`. Each file's header comment lists every stop, offset, alpha and noise parameter — the SVG is the canon; the Canvas code reproduces it into cached bitmaps.

v1.2 (planet pass) rewrote the two planet files only (9.7 KB / 11.3 KB — 9 742 / 11 287 bytes). Each is now an **animated** asset: a seamless texture strip (**one** `2P × 2r` rect — P = round(2π r) = 214 / 188 — whose filter stitches the noise to exactly P over a P-wide subregion (`stitchTiles="stitch"`) and repeats it across the rect with `feTile`; never two abutting rects, because their anti-aliased join shows as a 1 px hairline whenever the translate is fractional) scrolled through a `<clipPath>` circle by SMIL `<animateTransform type="translate" from="0 0" to="P 0">`, under lighting layers that never move; planet X's ring pulse, dash crawl and a new halo breathe are SMIL `<animate>` / `<animateTransform>` too. SVG features used beyond v1.1: `feComponentTransfer` (soft thresholds), `feTile`, `feMerge`, `<clipPath>` and SMIL; ids stay `ps*` / `px*`, no collisions with `star*`. Chrome renders all of it (verified via headless render); static renders and the mockups show **t = 0**, and the strips were verified seamless: translate 0 and translate P render byte-identical at 1× and 4×, and fractional translates (78.125 / 34.125 and 70.125 / 30.125 at 4×, 78.5 at 1×) show no join line (the first v1.2 cut, tile + `<use>`, did). Scroll sign: the brief's construction sketch writes `to="−<period> 0"` and `−((t/period)·W) mod W`, which would scroll east→west; the assets use `to="+P 0"` so the texture moves left→right as the brief's prose specifies (the brief contradicts itself on this point — copy the sign from the assets). Everything else is byte-identical to v1.1.

## Usage rules

- **Cached bitmaps (v1.1, v1.2).** The star is rendered **once** from its SVG recipe into a 400×400 sprite (at DPR, rebuilt on resize — a fixed-size bitmap that `drawImage` scales; the prototype never zooms past 2×) and blitted every frame; nothing in it (streamers, granulation, chromosphere, limb darkening) is ever drawn live. Each planet (v1.2) is **three** cached bitmaps per zoom bucket: a **surface strip** and a **cloud / wisp strip** — one tile P × 2r placed twice side by side = 428 × 68 (start) / 376 × 60 (X) CSS px at zoom 1, × DPR — and a **lighting overlay**, (2 · 1.12 r + 4) px square = 81 / 72 px, holding the limb squash, the glint (start only), the terminator, the 1 px limb line and the atmosphere rim. All three are rebuilt only when the zoom bucket changes, never on resize (`bucketZoom = 1.25^round(log zoom / log 1.25)`: buckets 25 % apart, flipping ±11.8 % about each centre, residual scale 0.894–1.118); the rotation phases live outside the bitmaps and survive a rebuild. The noise tiles (128 px; seeds 3 for the star, 7 + 19 for the start planet, 11 + 23 for X — five in all) are built once and kept. Planet X's halo and capture ring are drawn live around its bitmaps. Build costs: background ≈ 2.5 ms, star ≈ 1.5 ms, planets ≈ 2 ms each (both ≈ 4 ms in the same frame when the bucket flips) — once.
- **Planet strips (v1.2) — how to use them.** Period **P = round(2π r)** = 214 (start) / 188 (X) px at zoom 1 (it scales with the bucket zoom: P is the width of one tile, i.e. one full rotation). Per frame, per planet: `save` → `clip(arc r)` → `drawImage(surface, cx − r − P + φₛ · P, cy − r, 2P, 2r)` → `drawImage(cloud, cx − r − P + φ꜀ · P, …)` → `restore` → `drawImage(overlay)` — **1 clip + 3 blits** (the brief's "2 drawImage + clip" counts one strip; the cloud / wisp strip is the third), ≈ 0.08 ms. Two identical tiles make the strip 2P-periodic, so a phase φ in [0, 1) always covers the 2r window and φ → 1 is pixel-identical to φ = 0: that is the seamless modulo wrap, nothing to blend. Phases advance by **`dt / period`** from the wall clock — surface 90 s / clouds 64 s (start), surface 120 s / wisps 80 s (X) — wrapped with `x − floor(x)`, identical at 1x / 2x / 4x (weather, not simulation state), and they keep running under the result overlays. The texture moves **left→right** (the offset grows with time, the SVG's `translate 0 → +P`). Mind the sign: the brief's construction sketch writes `to="−<period> 0"` and `drawImage(surface, −((t/period)·W) mod W)`, which would scroll east→west; we use +P / a growing offset so the texture moves left→right as the brief's prose specifies — copy the sign from the assets and `canvas-notes.md` §4, not from the sketch. **Never round the offset**: at zoom 1 the start planet moves ≈ 0.04 px per frame and the fractional `drawImage` is what reads as motion. Cloud / wisp alpha is **baked** into the strip (0.5 / 0.35), so no `globalAlpha` per frame; the polar caps are bands inside the surface strip (they scroll, but as full-width bands they look fixed). The **lighting never rotates**: squash, glint, terminator, limb line and rim are in the overlay, fixed to the star vector L; never `ctx.rotate` a planet. Still **0 `shadowBlur`, 0 per-frame noise, blur or blend mode**. Canvas thresholds its own value-noise field by **percentile** (land p68, highlands p90, clouds p60, basins p72, veins 5 %, wisps 15 % — `canvas-notes.md` §4) so the *coverage* matches the asset rather than its exact pixels; start both phases at 0 (the SVG's t = 0 puts tile x 44 / 40 at the disc's left edge, and there is nothing in Canvas to align with that).
- Ship is 22 px long at zoom 1 and never smaller than 12 px on screen (`max(12, 22 · zoom)`); its 1 px outline and the cockpit dot are fixed screen px.
- Only the star and planet X glow (cached gradient sprite and live gradient halo). The start planet's atmosphere rim, its specular glint (a white α 0.35 ellipse inside the overlay, 0.22 r × 0.12 r) and the sky's halos are scatter inside fixed envelopes (1.12 r / r 4.5), not glow. Ship, trail, path, arrow and HUD are flat; `shadowBlur` is allowed once, on the result card, never on anything that moves; `multiply` / `destination-in` and the one `getImageData` / `putImageData` per strip layer run only inside bitmap builds, never in the frame loop.
- Capture ring: r 78 at zoom 1, 1.5 px, dash `[6, 6]`; the dashes crawl at −12 px/s via `lineDashOffset` **and** α pulses 0.35 ↔ 0.70 with radius ±2 px over 2.4 s (sine; the SVG's keyframes `0.55; 0.70; 0.55; 0.35; 0.55` / `78; 80; 78; 76; 78` start from the v1 rest state, so t = 0 is the static mockup); locks to α 1 (crawl stopped, r 78) on a win. Reset `setLineDash([])` and `lineDashOffset = 0` afterwards. Planet X's halo **breathes ±4 %** (radius scale 1 → 1.04 → 1 → 0.96 → 1) on the same 2.4 s sine, in phase with the ring — a live gradient radius, so it costs nothing; the breathe and the surface rotation keep running on a win, only the ring locks.
- Trail: 240 samples, 2 px, α 1 at the ship fading to 0 at the tail; per-segment or chunked alpha, no blur, no glow.
- Predicted path: round dots r 1.5 every 10 screen px, α 0.7, last 20 % at α 0.35, end ring r 6; dot spacing does not change with zoom, and it is never dashed lines (that would read as the trail).
- Drag arrow: tick at 242 · power px from the ship centre, shaft starts 16 px out, head 16 px; head and tick tint through `arrow.power` #3DE0C2 (0 %) → #FFC857 (50 %) → #FF5A5F (100 %), the label stays `ui.textMuted`.
- Thrust flash: two "lighter" triangles behind the hull, no blur, alive 1 frame per thrust tick; absent in every result overlay (engine off).
- Starfield and Milky Way: static, screen-space, no parallax, no twinkle; built once into the background canvas from the seeded rules (`canvas-notes.md` §2), exclusion zones star r 140 / start r 60 / X r 80 minimum (the asset keeps 70 / 100).
- HUD (all five mockups, canvas-notes §10): wordmark baseline (40, 50), mode label (40, 70), "FUEL" at x 1180 baseline 48, percentage right-aligned at x 1400 baseline 48, fuel bar 220×8 at (1180, 56), buttons centred on y 820 (Launch 160×44; [1x][2x][4x] 56×36 + Reset 96×36 with a 16 px gap), telemetry baseline (40, 864); weight 500 on wordmark / mode / FUEL.
- Result overlays: scrim `rgba(5,7,16,0.62)` over the whole scene including the HUD; card 520×232 centred at (720, 450), radius 16, `ui.panel` α 0.92, `ui.border`, 4 px accent bar, title 40 px weight 600, subtitle 16 px, "Fly again" 140×40; card shadow `rgba(5,7,16,0.5)`, blur 16 px (σ 8), offset y 8 — the one `shadowBlur`, drawn once.
- Line widths (ring 1.5, trail 2, dots r 1.5, arrow 2, outline 1, planet limb line 1) and all HUD geometry are screen px; body radii, positions, strip period P = round(2π r) and overlay geometry (squash 0.88–1.0 r, glint 0.45 r · L and 0.22 r × 0.12 r, 0.36 r shade offset, 1.25 r shade radius, 1.12 r rim) scale with zoom. The rotation periods (90 / 64 / 120 / 80 s) are wall-clock seconds and never scale — with zoom, or with the 1x / 2x / 4x speed buttons.
